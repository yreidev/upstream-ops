# 更新日志

每个版本一段，标题写成 `## vX.Y.Z（YYYY-MM-DD）`，版本内的小节用三级标题。

还没发版的改动先记在“未发布”下，发版时把这个标题改成版本号和日期，再打 tag。推送 `vX.Y.Z` tag 后，发布工作流会取对应段落作为 GitHub Release 的说明，并在末尾附上镜像地址和 digest；找不到对应段落会在构建镜像前失败。应用里“检测更新”发现新版本时，弹窗显示的就是这些 Release 说明。

## v0.5.0（2026-10-13）

### 新增

- CCH 成本倍率同步：每轮倍率采集后，把上游分组倍率同步成 Claude Code Hub 供应商的成本倍率。按站点地址和密钥尾号自动配对，不一致就改，并发送新的“CCH 倍率同步”通知；失败写监控日志并按连续失败去重通知。CCH 地址和管理令牌在设置页填写，令牌加密存数据库，可以先检查配对再手动同步。升级时已勾选部分事件的通知订阅会自动补上这个事件。
- 密钥管理里分组名旁边加了复制按钮，并新增“打开站点密钥页”按钮，在新标签页打开上游站点的密钥管理页（`/keys`）。有的站点只允许在它自己的网页上改密钥，可以复制分组名过去手动改。

### 修复

- 总览“最近通知”里的记录点了没反应，看不到正文。现在点一行就地展开正文和发送失败的原因，再点收起。
- 倍率变动通知的正文按 Markdown 显示，不再露出 `#`、`**` 这些符号；通知页发送记录的展开行同样处理。
- 有的 NewAPI 站点限制了谁能改动密钥，新建、修改、删除密钥会被上游以 403 拒绝。现在报错后面会说明怎么处理：只要求网页登录会话的，改填 Cookie 或改用账号密码登录；只接受站点自己网页发起改动的，到站点网页上操作。
- “名称改为分组名”有密钥改失败时只弹一条错误提示，不再同时弹出“已改名 0 个”的成功提示；原因相同的密钥合成一行显示。
- 设置页读的是配置文件、“应用”也只按配置文件生效，不认启动时的环境变量。只靠环境变量（比如 `AUTH_ENABLED`）开着登录时，在设置页点“应用”会把登录关掉。现在“应用”和启动一样以环境变量为准；设置页显示实际生效的值，由环境变量决定的项置灰并注明变量名，保存时也不会把环境变量的值写进配置文件。
- 登录退避和“已暂停自动登录”的状态原来只存在内存里，每次重启都会清空：因密码错误、封号、打码余额为 0 暂停的渠道，重启后会再自动登录一次，可能白花一次打码费。现在这些状态存进数据库（新表 `login_backoff_states`，启动时自动建），重启后接着生效。
- 手机上设置页底部的“应用 / 保存”栏不会浮在屏幕底部，只出现在表单末尾；手机上换页也不会回到页面顶部。原因是手机上滚的是整个页面，而内容区仍被设成了滚动容器。
- 读屏软件读到的按钮、图标名称有不少是英文（弹窗的 confirm / cancel / close、分页的 Previous / Next、表格的 Expand this row、标签、密码框等），现在都换成中文，弹窗底部按钮读按钮上的文字；图标不再读出 home、refresh 这类图标名。
- 渠道表单里“获取 Cookie”的说明改为从开发者工具的网络面板复制请求头里的整段 Cookie。原来写的“复制 session 的值”容易只拷到值、漏掉 `session=`，上游会当成未登录。

### 构建与发布

- 前端构建不再有警告：图表改为按需注册，VChart、Markdown 解析器、date-fns 单独成块，发新版时这些文件名不变，浏览器可以继续用缓存。
- CI 和发布工作流改用 Ubuntu 26.04 运行器，并去掉每次检出代码时的 git 默认分支提示和 pnpm 安装时的误报警告。

### 升级前注意

启动时会自动执行以下一次性迁移，建议先备份数据库：

- 新增 `cch_sync_configs`、`login_backoff_states` 两张表。
- 只勾选了部分事件的通知订阅补上 `cch_sync`（CCH 倍率同步）事件；没限定事件的订阅本来就能收到，不改。

## v0.4.0（2026-10-13）

### 变更

- 前端整体改用 [Semi Design](https://semi.design)，不再用 shadcn/ui 和 Tailwind；后端接口不变。原来的单页改成左侧导航分页：总览、渠道、倍率变化、上游公告、通知、打码平台、设置、监控日志，窄屏时导航收进抽屉。
- 渠道列表在桌面端改成表格，点开一行看分组倍率、备注和完整报错；窄屏仍是卡片。每页数量改为 10、20、50、100 或全部，之前存的每页数量不在新选项里时回到 20。
- 密钥管理改成从右侧滑出的抽屉。
- 通知渠道和发送记录都放在“通知”页，打码配置放在“打码平台”页，设置页不再重复这两块。
- 上游公告的 Markdown 改用 Semi 的渲染组件，公告里夹带的 HTML 按 GitHub 同款白名单过滤，脚本、事件属性、内联样式和 `javascript:` 链接都会去掉。
- 亮色、暗色、跟随系统的选择沿用原来存在浏览器里的值，升级后不用重新选。

### 新增

- “监控日志”页：查看登录、校验会话、余额、消费、倍率每次执行的结果和报错，可按渠道、任务和成败筛选。
- 设置页可以改“上游公告保留天数”，之前只能写配置文件。

### 修复

- 手动操作时浏览器断开连接（刷新、关闭页面）导致的请求取消不再当作失败：不写失败的监控日志、不改渠道报错、不删已保存的会话。之前会在渠道上留下“校验会话：… context canceled”，直到下一轮余额采集成功才消失。超时仍按失败处理。
- 新增渠道时关掉“监控”、新增通知渠道或打码配置时关掉“启用”，保存后会变成开启。数据库层把这几个默认开启的开关当成没填，换成了默认值；现在按填写的值保存。已经建好的不受影响。

## v0.3.0（2026-10-13）

### 新增

- 密钥管理窗口新增“名称改为分组名”按钮，一键把当前渠道全部密钥的名称改成各自所属的分组名。已经同名、未分组、分组不在上游现有分组里的跳过；NewAPI 名称最长 50 字节，超长的也跳过。
- 检测更新发现新版本时弹窗显示当前版本之后各版本的更新日志；页头的“有新版本”和设置页的“可更新”也能点开查看。

### 修复

- NewAPI 修改密钥时先读出原有字段再整条写回。NewAPI 的修改接口会把没传的字段清零，之前“迁移 API Key”只传分组，会把名称、额度、过期时间一起清空，密钥随即被判为过期。
- NewAPI 编辑密钥时改启用、停用状态不生效：状态改为单独请求修改。

### 构建与发布

- 推送 `vX.Y.Z` tag 时按本文件自动创建 GitHub Release，末尾附镜像地址和 digest；本文件没写这个版本时不构建镜像。
- 检测更新改为读取 GitHub 的发布列表（仍只请求一次），按版本号取最新的正式发布，不再依赖 GitHub 标记的“最新”。

## v0.2.0（2026-10-13）

### 修复

- Sub2API 消费统计接口被屏蔽（404）时改用用量统计接口，不再每轮报错。
- 上游临时故障（5xx、超时）不再当作会话或 token 失效，不触发刷新和重新登录。
- 会话校验、消费采集、打码失败写入监控日志；消费采集失败不再挡住余额不足提醒。
- 定时登录失败按 15 分钟、30 分钟、1 小时、2 小时逐步退避；密码错误、封号、账号未激活、打码余额为 0 时暂停自动登录，修改渠道或打码配置、手动刷新、打码余额恢复后解除。手动刷新不受限制。
- 失败通知去重：同一类失败连续 2 次且跨度满 10 分钟才通知，之后每 6 小时最多提醒一次，恢复后发送“已恢复”通知；永久错误立即通知；打码失败单独上报。
- Telegram 改用 HTML 发送，格式解析失败时改发纯文本，遵守限频等待时间，超长截断；企业微信按错误码处理限频与地址失效，超过 4096 字节按字符边界截断。
- 发送错误与通知日志不再包含 Telegram Bot Token 和企业微信 Webhook key。

### 新增

- 通知订阅可选“全部渠道”，以后新增的上游也会自动包含。
- 新增“故障恢复”（`recovered`）通知事件。

### 构建与发布

- 推送 main 只跑测试（后端 gofmt、vet、test，前端 lint、tsc、build），推 tag 才构建镜像，构建前会先跑同一套测试；不再发布 `:edge` 镜像。

### 升级前注意

启动时会自动执行以下一次性迁移，建议先备份数据库：

- 选中了当时全部上游的订阅规则改为“全部渠道”，原来的渠道列表保留，回滚到 v0.1.0 仍能用。
- 事件列表非空的订阅补上 `login_failed`、`monitor_failed`、`recovered`，并去掉已移除功能的 `subscription_*` 事件。
- 旧通知日志错误信息里的 Telegram Bot Token、企业微信 Webhook key 替换成 `***`，不可恢复。
- 新增 `notification_failure_states`、`applied_migrations` 两张表。

## v0.1.0（2026-10-13）

[yreidev/upstream-ops](https://github.com/yreidev/upstream-ops) 的自用精简版，基于 bejix/upstream-ops v0.0.10，只保留自己用得到的功能。需要完整功能请使用上游仓库。

### 移除

- 请求转发网关（/v1 转发、分组、密钥、路由、供应商、用量、计价及对应页面）
- Sub2API 订阅管理与用量监控、订阅告警
- 全局代理及各处的代理开关
- MySQL 支持，只保留 SQLite
- 通知渠道只保留 Telegram 与企业微信；打码平台只保留 YesCaptcha

### 依赖与构建

- 后端最低 Go 1.26，gin 1.12、viper 1.21、gorm 1.31 等升级到最新；yaml 库换为仍在维护的 go.yaml.in/yaml/v3
- 前端 React 19.3、Vite 8、TypeScript 6.0、pnpm 12，并删掉了用不到的组件和依赖
- 镜像只提供 linux/amd64

### 升级前注意

启动时会自动执行以下迁移，**不可恢复，升级前请先备份数据库**：

- 删除表 `gateway_groups`、`gateway_keys`、`gateway_routes`、`gateway_providers`、`gateway_usage_logs`、`model_price_overrides`
- 删除列 `channels.subscription_enabled`、`channels.proxy_enabled`、`captcha_configs.proxy_enabled`、`notification_channels.proxy_enabled`
- 删除 Telegram、企业微信以外的通知渠道（通知日志保留）
- 删除 YesCaptcha 以外的打码配置，引用它们的上游渠道解除关联

环境变量 `DATABASE_DRIVER` 已不再使用，可以删除。
