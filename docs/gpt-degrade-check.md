# GPT 降智检测：方案记录

2026-10-13 逐条定下的方案，已按此实现；用法和接口见 README 的“GPT 降智检测说明”。以后改规则先改这里。

检测跑在后台任务机制上（见 README“后台任务”一节）：手动点的检测和定时巡检都由后端建任务、在后台跑、结果存库，页面只读状态。

## 方法：糖果题

参考 MIT 许可的 [haowang02/cpa-plugin-codex-candy-eval](https://github.com/haowang02/cpa-plugin-codex-candy-eval)。

- 发一道组合推理题，正确答案是 21。回答里出现不和其他数字相连的 `21` 就算答对。
- 每次记下模型、推理强度、是否答对、答案、输入 / 输出 / 推理 token 数和耗时。
- 不做模型指纹：每个分组要发 60 到 400 次请求，花费和耗时都大得多。

## 请求方式：模拟 Codex 新会话

- 照搬插件（提交 0de3802）的 Codex 上下文和请求头，模拟 codex-tui 0.160.0 新会话的第一个请求，发到中转站的 `/v1/responses`，流式返回，`include` 带 `reasoning.encrypted_content`。实现在 `backend/degrade`。
- 嵌入插件的内容时保留它的 MIT 版权声明（`backend/degrade/data/LICENSE-cpa-plugin-codex-candy-eval`）。
- 2026-10-13 实测：Sub2API 站和 NewAPI 站都接受这种请求，一次输入约 1.8 万 token、输出几百 token，30 秒左右答完。

## 测哪些密钥

在页面上按渠道手动挑上游密钥加入，只测加入的。不按分组名或密钥名自动识别，也不跟 CCH 的供应商走。

检测要用完整密钥。加入时先用渠道的“查看完整密钥”接口取一次；实测有的 NewAPI 站拒绝从接口取（403 `browser origin required`，只能在站点自己的网页上看），取不到就在页面上粘贴。两种来源都和渠道凭据一样加密存库，以后检测直接用，不依赖站点的登录状态。密钥在站点上被删或换掉后，检测记为请求失败，在这把密钥的“更多”里点“重新取密钥”。

## 模型和推理强度

全局默认 `gpt-6.1-sol`、`low`，单个密钥可以单独改。

实测分组里不一定有这个模型：没有时站点直接返回 503（NewAPI 是 `model_not_found`），不扣费。分组能用哪些模型可以用这把密钥请求 `GET /v1/models` 查，不扣费。

## 什么时候跑

- 手动：页面上随时点“检测”，和定时巡检一样跑一轮下面的确认流程，结果会改状态、会通知。
- 定时：按 Cron 巡检，默认关闭，每轮在后台任务页记一条。

## 状态确认

照搬插件巡检脚本的规则，每个密钥有一个确认过的状态（未确认、正常或降智），每轮先测一次：

| 当前状态 | 首测 | 处理 |
| --- | --- | --- |
| 正常 | 答对 | 保持，不复测 |
| 正常 | 答错 | 马上再测两次，三次都答错才确认降智 |
| 降智 | 答错 | 保持，不复测 |
| 降智 | 答对 | 等 240 秒再测两次，三次都答对才确认恢复 |

三次结果不一致、请求失败或记录不全时，状态不变、不通知。

新加入的密钥是“未确认”，这点和插件不同（插件当作降智）：首测后马上再测两次，三次一致才定为正常或降智，不一致就保持未确认、等下一轮。

## 结果处理

只通知：确认降智、确认恢复，或未确认的密钥第一次定为降智时，走现有通知渠道发一条，写明渠道、密钥（分组）、模型和判定；第一次定为正常不发。不自动停用 CCH 里的供应商。

## 记录保留

每次检测的记录跟监控日志的保留天数，由“清理过期历史”一起删，天数为 0 时永久保留。确认过的状态不受影响。

## 界面

侧边栏新增“降智检测”页：列出加入的密钥和状态、最近一次结果、模型和推理强度，有“检测”和“全部检测”按钮，展开看历次回答；在这页按渠道挑密钥加入。设置页放巡检 Cron 和默认模型、推理强度。
